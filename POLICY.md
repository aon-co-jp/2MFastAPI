## 2026-11-26 変換の安全方針(Laravel) / Conversion safety policy (Laravel)
**日本語**: 変換で意味が変わる恐れがあるものは訳さず 501 にする。特にミドルウェア(認証・権限)は、利用者が `MIDDLEWARE` に実装を入れるまで該当ルートを動かさない。データベースへの一括代入は、表にある列だけに限る(主キーは入れない)。Blade の `{{ }}` は Jinja2 の自動エスケープで同じく安全に表示する。`{!! !!}` は元と同じくエスケープしない。CSRF 保護は変換されないので、フォームを受けるルートを公開する前に別途対策する。
**English**: Anything whose meaning a conversion could change is not translated and answers 501. Middleware (auth, permissions) in particular keeps its routes closed until the user puts an implementation in `MIDDLEWARE`. Mass assignment to the database is limited to the table's columns (never the primary key). Blade `{{ }}` stays escaped through Jinja2 autoescaping; `{!! !!}` stays unescaped as in the original. CSRF protection is not converted, so add your own before exposing routes that accept forms.

## 2026-11-26 変換の安全方針の追記(検証・SQL) / Conversion safety addendum (validation, SQL)
**日本語**: `$request->validate()` は、対応している規則だけで構成されるときに限り変換し、1つでも知らない規則があればルートを 501 にする(検証が抜けた状態で公開しない)。生 SQL(`DB::select`)は `?` のバインドだけを許し、値を SQL 文字列に埋め込まない。一括更新・削除(`where()->update()`/`->delete()`)は元の条件をそのまま使い、条件を広げない。
**English**: `$request->validate()` is converted only when every rule is supported; one unknown rule makes the route 501 (never expose a route with validation silently dropped). Raw SQL (`DB::select`) allows only `?` bindings; values are never pasted into the SQL string. Bulk update and delete (`where()->update()`/`->delete()`) keep the original conditions and never widen them.

## 2026-11-27 追記: Eloquent/DB の orWhere・whereIn・whereNotIn・whereNull・whereNotNull / Update: orWhere, whereIn, whereNotIn, whereNull, whereNotNull
**日本語**: Laravel→MFastAPI 変換が `orWhere`・`whereIn`・`whereNotIn`・`whereNull`・`whereNotNull` に対応(SQLAlchemy Core の `or_`/`and_`/`in_`/`is_`。`where(a)->where(b)->orWhere(c)` は Laravel と同じ `(a AND b) OR c`)。例 `examples/laravel_app` に `/api/report2` を足し、テスト21件が成功(新規 `test_or_where_in_null`、変換できたルートは33本=1本増)。**未対応**: テーブルの結合(join)、`with()` の事前読み込み、多対多、session、名前付きスロット。
**English**: The Laravel-to-MFastAPI conversion now handles `orWhere`, `whereIn`, `whereNotIn`, `whereNull` and `whereNotNull` (SQLAlchemy Core `or_`/`and_`/`in_`/`is_`; `where(a)->where(b)->orWhere(c)` becomes `(a AND b) OR c`, as in Laravel). Added `/api/report2` to `examples/laravel_app`; 21 tests pass (new `test_or_where_in_null`; converted routes 33, one more). **Not yet**: joins, `with()` eager loading, many-to-many, session, named slots.

## 2026-11-27 追記(2): DB::table の join / leftJoin / Update (2): join and leftJoin
**日本語**: Laravel→MFastAPI 変換が `DB::table(..)->join('t2','a.x','=','t2.y')` と `leftJoin`(3引数・4引数)に対応。`表.列` の形の列名(where・orderBy)も解決でき、結果は両方の表の列を1行にまとめる(列名が重なるときは後ろの表が勝つ。Laravel/PDO と同じ)。件数(`count`)も結合込みで数える。例 `/api/joined`・`/api/joined-count` を追加し、テスト22件が成功(新規 `test_joins`、変換できたルート35本)。**限界**: 結合つきの `update`/`delete`、複数列の `on`、`select()` で列を絞る指定は未対応。**未対応**: `with()` の事前読み込み、多対多、session、名前付きスロット。
**English**: The Laravel-to-MFastAPI conversion now handles `DB::table(..)->join('t2','a.x','=','t2.y')` and `leftJoin` (3- and 4-argument forms). Qualified `table.column` names work in `where` and `orderBy`; each result row merges the columns of both tables (on a name clash the later table wins, as in Laravel/PDO), and `count` counts over the join. Added `/api/joined` and `/api/joined-count`; 22 tests pass (new `test_joins`; 35 routes converted). **Limits**: `update`/`delete` with joins, multi-column `on`, and narrowing columns with `select()` are not supported. **Not yet**: `with()` eager loading, many-to-many, session, named slots.

## 2026-11-27 追記(3): Eloquent の with()(事前読み込み) / Update (3): with() eager loading
**日本語**: Laravel→MFastAPI 変換が `Model::with('rel')`(文字列を複数並べた形も可)に対応。結果へリレーション名のキーで関連データを入れる(`hasMany`=配列、`hasOne`・`belongsTo`=1件または null)。関連は `find`/`get`/`first` の結果に付く。例 `/api/users-with-orders`・`/api/orders-with-owner`(Order の `user()` へ `with('user')`)を追加し、テスト23件が成功(新規 `test_with_eager_loading`、変換できたルート37本)。**限界**: 行ごとに関連を1回ずつ引くので N+1 の問い合わせになる(Laravel の事前読み込みは1回にまとめる)。`with('a.b')`(入れ子)・条件つきの `with` は未対応(TODO で残る)。**未対応**: 多対多、session、名前付きスロット。
**English**: The Laravel-to-MFastAPI conversion now handles `Model::with('rel')` (several quoted names also work). Related data is attached under the relation name (`hasMany` = list, `hasOne` and `belongsTo` = one record or null), for the results of `find`, `get` and `first`. Added `/api/users-with-orders` and `/api/orders-with-owner` (`with('user')` on Order's `user()`); 23 tests pass (new `test_with_eager_loading`; 37 routes converted). **Limits**: relations are fetched once per row, so it is an N+1 query pattern (Laravel's eager loading batches them into one). Nested `with('a.b')` and constrained `with` are not supported (left as TODO). **Not yet**: many-to-many, session, named slots.
